## What to build

Create a reusable Avatar component that handles the fallback state for users without a custom profile picture. When a user's avatar URL is null, the component should generate and display deterministic initials based on their name. The background color of the avatar should be consistently generated by hashing the user's UUID, ensuring the same user always gets the same color across sessions. Integrate this component into the ProfileScreen to replace the existing plain text or default image fallback.

This issue follows the TDD approach: write failing tests for the Avatar component's initial extraction and color generation logic before implementation.

## Acceptance criteria

- [x] `Avatar` component extracts the first letter of `displayName` (or `first_name` if `displayName` is unavailable).
- [x] `Avatar` component generates a deterministic background color based on the user's `id` (UUID).
- [x] `Avatar` component renders a circular badge with the calculated color and centered initial in white text when `avatarUrl` is null.
- [x] `ProfileScreen` uses the new `Avatar` component to display the user's profile picture.
- [x] TDD: Tests verify the initial extraction and deterministic color generation logic through the public interface.
